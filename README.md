# 실험실 — 호기심이 실험이 되는 곳

과학을 공부하는 누구나 관심사와 준비물에 맞는 실험을 찾고 나눌 수 있는 한국어 웹 서비스입니다. 과학고 1학년의 탐구를 시작점으로 설계했으며, 회원가입 없이 사용할 수 있는 첫 번째 구현입니다.

화면 미리보기: [GPT 키 입력](docs/screenshots/gpt-key.png) · [데스크톱](docs/screenshots/home.png) · [모바일](docs/screenshots/mobile.png)

## index.html 바로 열기

이 저장소의 루트 **`index.html`을 다운로드해서 더블클릭하면** 별도 설치나 서버 없이 앱을 사용할 수 있습니다. Chrome·Edge·Firefox·Safari 등 최신 브라우저를 사용하세요. 화면, 스타일, 기본 실험 9개, 검증 및 추천 로직을 파일 하나에 포함했습니다. 기본 기능은 외부 이미지·폰트·API 요청 없이 동작하며, 인터넷 연결 없이도 설문·추천·피드백·실험 등록·저장 목록을 사용할 수 있습니다. 개인 키로 GPT를 질문할 때만 인터넷 연결이 필요합니다.

파일 버전과 GitHub Pages에서는 등록 실험, 배점, 추천 세션 및 의견을 **내 브라우저의 저장소**에 보관합니다. 파일을 같은 브라우저에서 다시 열면 이어서 사용할 수 있습니다. 다른 기기·브라우저·사용자와 데이터가 공유되지는 않으며 파일을 옮기거나 브라우저 데이터를 삭제하면 기존 저장 정보가 이어지지 않을 수 있습니다. 브라우저가 저장을 차단하면 현재 창에서만 사용하는 **임시 실험실**로 표시합니다.

**첫 화면에서 개인 GPT API 키를 입력하면 파일/Pages에서도 GPT에게 질문할 수 있습니다.** 키는 앱의 현재 페이지 메모리에만 보관하며 저장소나 HTML 파일에 기록하지 않습니다. 새로고침·페이지 이탈 시 다시 입력해야 합니다. 키가 없으면 기본 가이드를 제공합니다.

### GitHub Pages에 공개하기

현재 주소는 **https://hyunk1-hong.github.io/ddshs1316/** 입니다. 이 PR을 `main`에 병합하면, 현재 설정(`main` 브랜치의 루트 `/`)에서 완성된 단일 `index.html`을 그대로 게시할 수 있습니다. 별도로 Node 서버를 실행하거나 Pages 설정을 바꿀 필요가 없습니다. `.nojekyll` 파일을 함께 둡니다. 병합 후 Pages 배포 완료까지 잠시 기다리세요.

파일과 Pages에서 보이는 내용은 브라우저 개인용입니다. 다른 사람이 등록한 실험을 함께 보거나 피드백을 전체 사용자에게 적용하려면 서버 버전을 배포해야 합니다.

### 화면 소스 수정하기

루트 `index.html`은 **자동 생성 파일**입니다. 직접 수정하지 말고 `src/` 또는 `shared/`를 수정한 다음 아래 명령으로 다시 만드세요.

```bash
npm ci
npm run build:standalone
```

`npm run build`도 루트 파일을 갱신합니다. 변경한 `index.html`을 함께 커밋하세요. CI에서는 재빌드 결과가 저장된 파일과 같은지 검사합니다. 파일 버전은 운영체제의 기본 한글 폰트를 사용합니다.

## 서버 버전 실행하기

전체 사용자 데이터 공유나 서버의 공용 GPT 키를 사용하려면 Node.js **24 이상**이 필요합니다. SQLite는 Node 내장 모듈을 사용합니다.

```bash
npm ci
cp .env.example .env
npm run dev
```

개발 웹 서버는 기본 5173번, API 서버는 3001번 포트에서 실행됩니다. Vite가 `/api` 요청을 Node 서버로 전달합니다. `.env` 없이도 설문·추천·피드백·등록 및 기본 원리 가이드는 작동합니다. 서버 버전은 브라우저 저장소로 자동 전환하지 않습니다.

프로덕션에서는 한 서버가 API와 `dist`의 화면을 함께 제공합니다.

```bash
npm run build
npm start
```

서버 버전의 HTML 소스는 `src/index.html`, 개발 시작점은 `src/main.tsx`, 파일 버전 시작점은 `src/standalone.tsx`입니다. `dist/index.html`은 서버 배포용이고 루트 `index.html`은 직접 열기/Pages용입니다.

`data/lab.sqlite`에 실험, 추천 세션, 항목별 배점과 피드백을 저장합니다. 재시작해도 데이터가 유지됩니다. 배포할 때 `DATABASE_PATH`를 영구 저장 볼륨에 지정하고 데이터베이스를 백업하세요. 서버 버전은 단일 인스턴스를 기준으로 합니다.

## GPT 연결

### 브라우저 개인 키 (파일·GitHub Pages·서버 화면)

1. 첫 화면의 **GPT와 더 깊이 탐구하기**에서 `sk-`로 시작하는 본인 API 키를 입력하고 **GPT 사용하기**를 누릅니다.
2. 실험 카드를 열고 **AI 학습 도우미**에서 원리나 통제 변인을 질문합니다.
3. **키 삭제**를 누르면 키 참조를 제거하고 진행 중 요청을 취소합니다. 키를 바꿀 때도 이전 요청 결과를 사용하지 않습니다.

키 입력만으로 API를 호출하지 않습니다. **개인 키 설정됨**은 형식이 맞는 키를 메모리에 보관했다는 뜻이며, 실제 유효성과 모델 접근 권한은 질문할 때 확인합니다. 연결은 브라우저에서 `https://api.openai.com/v1/responses`로 직접 이루어지고 개인 키는 OpenAI 인증 헤더에만 넣습니다. 앱 서버에는 개인 키를 보내지 않습니다.

앱은 키를 localStorage·sessionStorage·쿠키·데이터베이스·로그·생성 HTML에 쓰지 않습니다. 새로고침이나 페이지 이탈 후 재입력해야 합니다. 이 방식은 이 사이트의 브라우저 JavaScript에 개인 키를 맡기는 방식입니다. 키를 코드나 다른 사람과 공유하지 마세요.

모델은 `gpt-4.1-mini`, 질문 1,000자, 응답 최대 900토큰, 타임아웃 20초, 한 페이지 기준 분당 5회입니다. 질문과 해당 실험 가이드가 OpenAI로 전송되고 사용 비용이 발생할 수 있습니다. 쿠키는 전송하지 않고 리디렉션 및 응답 캐시를 사용하지 않으며 `store: false`를 설정합니다. 401(키), 403(권한), 429(한도) 및 네트워크 오류를 구분해 안내하고 업스트림 오류 본문은 표시하지 않습니다. 기본 실험 원리는 오류가 나도 계속 볼 수 있습니다.

### 서버 공용 키 (선택)

개인 키가 설정되어 있으면 개인 키를 우선 사용합니다. 개인 키가 없으면 서버 버전은 기존 서버 키를 사용할 수 있고 파일/Pages 버전은 기본 가이드를 보여줍니다.

로컬 `.env` 또는 배포 서버의 비밀 환경 변수에 다음을 설정하세요. **키를 채팅, 소스 코드, PR, 브라우저 환경 변수에 넣지 마세요.**

```dotenv
OPENAI_API_KEY=여기에_서버용_키_설정
OPENAI_MODEL=gpt-4.1-mini
```

Codex 클라우드 환경에서는 예약된 `OPENAI_` 이름 대신 환경 설정의 비밀 변수 **`LAB_GPT_API_KEY`**를 사용합니다. 서버는 이 변수가 있으면 우선 사용하고, 없으면 로컬 `OPENAI_API_KEY`를 사용합니다. 허용 HTTPS 목적지는 `api.openai.com`입니다.

서버 공용 키 모드에서는 실험 상세 화면의 **AI 학습 도우미**에서 질문하면 서버가 OpenAI Responses API를 호출합니다. 키는 클라이언트 번들에 포함되지 않습니다. 모델은 환경 변수로 변경할 수 있습니다. 서버에서 `api.openai.com`에 HTTPS로 접근할 수 있어야 합니다.

- 키가 없으면 **기본 가이드**라고 표시하고 해당 실험의 원리를 반환합니다.
- 실제 API 호출이 실패하면 오류를 표시하며, 기존 실험 가이드는 계속 이용할 수 있습니다.
- GPT는 설명을 돕습니다. 추천 점수와 피드백 학습은 재현 가능한 서버 로직으로 계산합니다.
- 요청은 분당 5회/IP, 최대 1,000자, 응답은 최대 900토큰으로 제한합니다. 질문과 실험 데이터는 API 입력으로 전송되며 `store: false`를 사용합니다. 키를 넣으면 OpenAI 사용 비용이 발생할 수 있습니다.

실제 GPT 요청은 유효한 키와 사용 가능한 OpenAI 잔액·권한, 네트워크 접근이 필요합니다. 자동 테스트는 가짜 테스트 키와 모의 응답으로 요청·파싱·저장소 비저장·삭제·새로고침·오류를 검증하며 실제 과금 요청은 보내지 않습니다. 공개 API의 브라우저 preflight 응답도 확인했습니다. 실제 개인 키를 사용한 호출은 아직 검증하지 않았습니다.

## 네 가지 핵심 기능

### 1. 순차 설문과 추가 질문

관심 분야 → 탐구 목적 → 난이도 → 시간 → 장소 → 준비물 → 예산의 공통 질문을 사용합니다. 특정 분야를 고르면 해당 분야의 세부 관심사를 추가로 묻습니다. 전체 분야를 고르면 추가 질문은 생략합니다. 이전 답변으로 돌아갈 수 있으며 분야 변경 시 이전 세부 답변을 지웁니다. 서버에서도 답변 조합을 검증합니다.

### 2. 질문별 가중치 추천

각 실험은 답변 선택지별로 0~1 사이의 적합도 프로필을 가집니다.

| 질문               | 가중치 |
| ------------------ | -----: |
| 관심 분야          |      5 |
| 탐구 목적          |      4 |
| 준비물             |      4 |
| 실험 장소          |      4 |
| 난이도             |      3 |
| 시간               |      3 |
| 예산               |      2 |
| 분야별 세부 관심사 |      2 |

`일치율 = 100 × Σ(항목 적합도 × 가중치) / Σ(응답한 항목의 가중치)`

초기 적합도는 실험 메타데이터로 계산합니다. 예를 들어 시간·예산은 한도 대비 비율, 준비물은 필요한 도구 중 보유한 도구의 비율입니다. 준비물의 복수 선택은 정렬한 집합을 하나의 응답값으로 취급합니다. 점수 내림차순으로 상위 6개를 제시하고 동점은 피드백 신뢰도, 실험 ID 순으로 정렬합니다. 부족한 도구, 초과 시간·예산, 부적절한 장소는 별도 경고를 표시합니다.

결과에서 항목별 배점과 가중치를 펼쳐 볼 수 있습니다. **일치율은 안전성이나 성공 확률이 아닙니다.**

### 3. 피드백으로 배점과 신뢰도 갱신

만족이면 해당 추천에서 답변한 모든 항목에 긍정 피드백을 추가하고 적합도를 `s + 0.08 × (1-s)`로 갱신합니다. 불만족이면 선택한 항목의 현재 응답값만 `s × 0.85`로 조정하고 부정 피드백을 추가합니다. 다른 질문과 다른 선택지의 배점은 그대로 유지합니다.

항목별 피드백 신뢰도는 베타 사전값을 사용하는 긍정 비율입니다. 편집 실험은 3:1(75%), 커뮤니티 실험은 1:1(50%)로 시작합니다. 항목별 신뢰도를 질문 가중치로 평균해 표시합니다. 사전값은 제품의 초기 가정이며 통계적으로 검증된 안전성 지표가 아닙니다.

7일 유효 추천 세션에 포함된 실험만 평가할 수 있으며, 세션·실험별로 한 번만 피드백을 받습니다. 서버는 SQL 트랜잭션과 고유 제약, 파일 버전은 저장된 세션별 평가 목록으로 중복 반영을 차단합니다. 브라우저 버전은 최근 100개 추천 세션을 유지합니다. 의견은 각 버전의 저장소에 보관되며 **다음 추천**부터 반영됩니다.

### 4. 사용자 실험 등록

이름·소개·분야·세부 관심사·난이도·목적·시간·예산·도구·장소·준비물·순서·안전 안내·과학 원리·닉네임·HTTPS 참고 출처를 모두 작성합니다. 현재 추천 설문 범위에 맞춰 5~120분, 소모품 3만원 이내의 실험을 지원합니다.

등록 실험의 초기 프로필은 메타데이터에서 구한 적합도 85%와 가장 유사한 기존 실험 최대 3개의 프로필 평균 15%를 결합합니다. **커뮤니티 · 임시 배점 / 검토 전**으로 표시하며 피드백에 따라 조정됩니다. 자동 배점이나 AI 설명은 실험의 안전성 검토를 대신하지 않습니다.

추가로 4개 분야의 기본 실험 9개, 준비물·순서·원리·안전 가이드, 검색과 분야 필터, 브라우저 로컬 저장 목록, 모바일 화면, 키보드 포커스와 네이티브 접근성 대화상자를 제공합니다. 자체 SVG 그림을 사용합니다. 서버 버전은 자체 제공 한글 폰트, 파일 버전은 운영체제 한글 폰트를 사용하며 외부 이미지·폰트 서비스에 의존하지 않습니다.

## 검증

```bash
npm run build             # TypeScript 검사 + 서버 화면 + 단일 index 생성
npm test                  # 로직/API/브라우저 저장소 테스트 31개
npm run test:e2e           # 서버 사용자 흐름 5개
npm run test:standalone    # 실제 파일 열기·인터넷 없이 이용·Pages 경로·개인 GPT 7개
```

E2E는 별도 임시 SQLite 파일을 사용합니다. `/usr/bin/chromium`이 있다면 사용하고, 없으면 `npx playwright install chromium`으로 설치하세요. 다른 경로는 `CHROMIUM_PATH`로 지정할 수 있습니다. GitHub Actions에서 빌드·생성 파일 일치·로직/API·브라우저 검사를 실행합니다. 일부 관리형 브라우저는 정책상 `file://` 접근을 차단합니다. 그런 환경에서는 파일 테스트가 관리자 정책 오류로 실패할 수 있으며, 일반 브라우저를 사용하는 CI에서 직접 파일 실행을 검증합니다.

- 설문 분기, 가중치 순위, 장비/장소 제약
- 피드백의 선택 항목 조정, 중복 제출 방지, SQLite 재시작 유지
- 필수 등록 항목과 HTTPS 출처 검증, 신규 실험 추천 반영
- GPT 기본 가이드, 서버 비밀 처리, Responses API 파싱, 연결 실패
- 실제 화면에서 설문→추천→피드백→상세→저장, 검색/필터, 실험 등록, 모바일 탐색
- 실제 `file://` 문서에서 인터넷 차단 상태 추천·피드백 및 재열기 유지
- 단일 HTML만 하위 경로에 게시했을 때 외부 파일/API 요청이 없는지 확인
- 손상된 브라우저 데이터 보호, 저장 차단/공간 초과 처리 및 서버와 점수 동일성
- 개인 키 메모리 보관, OpenAI에만 인증 헤더 전송, 앱 서버·저장소에 키 없음
- 키 삭제/교체 시 요청 취소, 새로고침 재입력, 401/403/429/타임아웃 및 호출 제한
